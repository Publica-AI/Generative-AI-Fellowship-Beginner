## What This Demo Teaches

- Writing the DELETE endpoint — 204 No Content
- Handling `IntegrityError` with `db.rollback()` and a 400 response

## Demo Steps

### Part 1 — Add Request and Update Schemas (5 min)

**Open `schemas.py`. Add the two new schemas:**
```python
class ProductCreate(BaseModel):
    name: str
    description: Optional[str] = None
    price: float
    category: Optional[str] = None
    stock: int = 0

class ProductUpdate(BaseModel):
    name: Optional[str] = None
    description: Optional[str] = None
    price: Optional[float] = None
    category: Optional[str] = None
    stock: Optional[int] = None
```

> "ProductCreate is what the client sends to create a product — no id, no created_at. Those are auto-generated by MySQL. ProductUpdate is for edits — every field is Optional because the client might only want to change the price, not everything."

---

### Part 2 — POST /products (10 min)

**Open `main.py`. Update the imports:**
```python
from fastapi import FastAPI, Depends, HTTPException, status, Response
from sqlalchemy.exc import IntegrityError
from schemas import ProductCreate, ProductOut, ProductUpdate
```

**Add the POST endpoint:**
```python
@app.post("/products", response_model=ProductOut, status_code=status.HTTP_201_CREATED)
def create_product(product: ProductCreate, db: Session = Depends(get_db)):
    new_product = Product(**product.model_dump())
    try:
        db.add(new_product)
        db.commit()
        db.refresh(new_product)
        return new_product
    except IntegrityError:
        db.rollback()
        raise HTTPException(status_code=400, detail="A product with this name already exists")
```

**Start the server:**
```bash
uvicorn main:app --reload
```

**Open /docs. Test POST /products:**

Request body to type in /docs:
```json
{
  "name": "Dangote Cement 50kg",
  "price": 7500,
  "category": "construction",
  "stock": 150
}
```

> "Watch the response — status 201, and the response includes an id field. That id came from MySQL. We did not send it; MySQL generated it. db.refresh() pulled it back into our object."

**Test the duplicate prevention** — try posting the same product name again:

> "Status 400. Clean error message. Without the try/except, this would have been a 500 with a raw MySQL error message leaking database internals. Always handle IntegrityError."

---

### Part 3 — Upgrade GET /products With Filters (5 min)

**Update the GET /products endpoint:**
```python
from typing import Optional

@app.get("/products", response_model=List[ProductOut])
def get_all_products(
    category: Optional[str] = None,
    skip: int = 0,
    limit: int = 10,
    db: Session = Depends(get_db)
):
    query = db.query(Product)
    if category:
        query = query.filter(Product.category == category)
    return query.offset(skip).limit(limit).all()
```

**Test in /docs:**
- Call without parameters — returns all products (up to 10)
- Call with `category=construction` — returns only construction products
- Call with `skip=1&limit=2` — returns products 2 and 3

> "This is pagination. Every production API needs it. Without a limit, GET /products on a Jumia-scale database would return millions of records and crash the server."

---

### Part 4 — PUT /products/{id} (10 min)

**Add the PUT endpoint:**
```python
@app.put("/products/{product_id}", response_model=ProductOut)
def update_product(
    product_id: int,
    product_data: ProductUpdate,
    db: Session = Depends(get_db)
):
    product = db.query(Product).filter(Product.id == product_id).first()
    if product is None:
        raise HTTPException(status_code=404, detail="Product not found")

    for field, value in product_data.model_dump(exclude_unset=True).items():
        setattr(product, field, value)

    db.commit()
    db.refresh(product)
    return product
```

**Test in /docs — update just the price of product id=1:**
```json
{
  "price": 8500
}
```

> "We only sent price. model_dump(exclude_unset=True) gives us only the fields that were in the request — just price. The for loop calls setattr(product, 'price', 8500). Then commit. Then refresh. Then we get the full updated product back."

**Ask students:** "What would happen if we used model_dump() without exclude_unset=True?"

Run GET /products/{id} on the same product.

> "The name, description, category, and stock are all still there — unchanged. Only price changed. That is the correct behaviour."

### Part 5 — DELETE /products/{id} (5 min)

**Add the DELETE endpoint:**
```python
@app.delete("/products/{product_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_product(product_id: int, db: Session = Depends(get_db)):
    product = db.query(Product).filter(Product.id == product_id).first()
    if product is None:
        raise HTTPException(status_code=404, detail="Product not found")

    db.delete(product)
    db.commit()
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

**Test in /docs:**
1. Create a test product (e.g. "Test Product")
2. Note its id
3. Call DELETE /products/{id} with that id — status 204, empty body
4. Try GET /products/{id} with the same id — status 404

> "204 means success but nothing to return. The product is gone. Try to GET it — 404. It is permanently deleted from MySQL."

**Also test 404 for a non-existent id:**

> "Delete on id=9999 — 404 because we check first whether it exists before trying to delete."

### Part 6 — Add the User Model (5 min)

**Open `models.py`. Add the User model:**
```python
class User(Base):
    __tablename__ = "users"

    id            = Column(Integer, primary_key=True, index=True)
    name          = Column(String(100), nullable=False)
    email         = Column(String(255), unique=True, nullable=False)
    password_hash = Column(String(255), nullable=False)
    role          = Column(String(20), default="user")
    created_at    = Column(TIMESTAMP, server_default=func.now())
```

**Open `schemas.py`. Add UserOut:**
```python
class UserOut(BaseModel):
    id: int
    name: str
    email: str
    role: str

    class Config:
        from_attributes = True
```

**Run create_all to create the users table:**
```python
# Temporarily in main.py after imports — remove after running once
from database import engine, Base
import models
Base.metadata.create_all(bind=engine)
```

Restart uvicorn, then remove the create_all call.

> "The users table is now in MySQL. Notice that password_hash is in the model but NOT in UserOut. That means it will never appear in any API response that uses UserOut as its response_model. This is intentional security — hashed passwords stay in the database."

## Common Student Issues to Watch For

| Issue | What to say |
|-------|-------------|
| POST returns 500 with "object is not JSON serializable" | "Check that your response_model is set to ProductOut and that ProductOut has `from_attributes = True` in its Config." |
| IntegrityError not caught — 500 returned | "The try/except must wrap `db.add()`, `db.commit()`, and `db.refresh()` together. Make sure the except block calls `db.rollback()` before raising HTTPException." |
| PUT updates all fields to None | "You are using `model_dump()` instead of `model_dump(exclude_unset=True)`. The `exclude_unset=True` is essential for partial updates." |
| DELETE returns 200 instead of 204 | "Set `status_code=status.HTTP_204_NO_CONTENT` on the decorator and return `Response(status_code=status.HTTP_204_NO_CONTENT)` explicitly." |
| model_dump() not found | "If you are on an older version of Pydantic (v1), use `.dict()` instead of `.model_dump()`. Run `pip show pydantic` to check your version." |
| User table not created | "Make sure `import models` runs before `Base.metadata.create_all()` — the import registers the User class with Base." |
